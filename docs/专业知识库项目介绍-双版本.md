### GitHub 仓库简介

### README 开篇介绍

## 项目简介

这是一个面向财务、审计、会计咨询和企业财务报告工作建设的企业会计准则专业知识库。项目基于开源知识库引擎 GroundMap 构建，将分散在准则原文、应用指南、企业会计准则解释、财政部实施问答、应用案例、监管规定和实务指引中的内容，整理为相互链接、可以核对来源、能够持续维护的 Markdown 知识体系。

知识库不是简单的文件目录，也不是把文档机械切片后临时拼接答案。外部 AI agent 会阅读完整页面或完整章节，先忠实整理每份来源，再把多份资料沉淀到长期维护的专业概念页中。每项重要结论尽量指向原始资料中的具体标题、段落或表格；当规则修订、官方解释变化或不同资料存在冲突时，系统保留来源、修改记录和处理过程。

目前知识体系以《企业会计准则 - 基本准则》和第 1 号至第 42 号具体准则为主干，并按照以下层次组织：

- **来源层**：准则原文、应用指南、准则解释、财政部实施问答、应用案例、监管资料及专业实务指引；
- **概念层**：存货、长期股权投资、固定资产、收入、所得税、企业合并、租赁、金融工具、合并财务报表等专业主题；
- **子专题层**：围绕定义与适用范围、确认、计量、终止确认、列报、披露、衔接规定和常见实务问题展开；
- **分析层**：会计政策选择、准则间衔接、争议事项、审计关注点、所需证据和典型案例分析；
- **导航层**：通过准则体系、重点专题、财政部官方资料、监管与披露、实务案例等索引定位内容。

本项目的目标，是把“散落的专业资料”转化为“可查询、可核验、可更新、可复核、可传承的专业知识资产”。

## 核心能力

- **以专业概念为中心**：准则文件属于来源，准则标题对应的专业事项属于概念，收入确认、可变对价、主要责任人和代理人等属于概念下的子专题，避免把文件名称和专业问题混在同一层级。
- **官方依据与实务资料并重**：统一组织准则原文、应用指南、准则解释、财政部问答、应用案例、监管口径和实务指引，并明确不同来源的性质和效力层级。
- **原文块级溯源**：重要结论通过稳定锚点指向原始资料中的具体标题、段落或表格，便于迅速核对上下文，而不是只显示笼统的文件名称。
- **完整上下文优先**：AI agent 阅读完整页面或完整章节，减少机械切片造成的断章取义、条件遗漏和例外条款缺失。
- **从规则到工作判断**：不仅回答“准则怎么规定”，还可以围绕交易事实、会计处理、报表列示、披露要求、审计风险和证据清单组织分析。
- **知识持续积累**：新资料摄入后会反查已有页面，识别需要更新的概念、相关准则、补充证据和潜在冲突，而不是孤立地新增一份摘要。
- **冲突不被静默覆盖**：新旧资料出现不一致时，保留双方观点及来源，交由使用者决定保留旧观点、采纳新证据、合并表述或继续观察。
- **健康度可检查**：自动检查待更新页面、失效引用、缺失来源、过粗引用、孤立页面、状态问题和未完成摘要，让知识缺口能够被发现。
- **修改过程可审计**：Markdown 是唯一真相源，Git 记录每次修改，可查看差异、复核提交或回滚；SQLite 索引只是可以重建的派生层。
- **原始资料受保护**：原件与个人笔记默认保留在本地私有目录，不进入公开仓库；公开内容与私人资料可以通过 `KB_ROOT` 分离管理。

## 典型使用场景

- 判断一项交易应适用哪项准则及哪些具体条款；
- 查询会计事项的确认、初始计量、后续计量、终止确认、列报和披露要求；
- 比较准则原文、应用指南、准则解释、实施问答和应用案例之间的关系；
- 分析收入总额法与净额法、资产处置损益、金融资产分类、租赁期、合并范围等实务问题；
- 根据初步会计判断整理合同、审批、估值、付款、交付和管理层判断等证据清单；
- 复核会计政策选择、重大判断、报表列示及附注披露是否具备充分依据；
- 将学习笔记、项目经验和高频问题逐步沉淀为经过来源校验的专题知识；
- 追踪规则修订、知识更新、未决冲突和历史判断的演进过程。

## 回答问题的方法

一次专业查询通常沿“总索引 - 领域索引 - 概念页 - 来源摘要 - 原文锚点”的路径逐级下钻。一般性问题优先使用已经综合的概念页；涉及精确条款、数字、日期、例外条件或重大判断时，必须回到对应原文段落核验后再形成结论。最终回答应区分规则依据、事实前提、分析判断、仍需取得的证据和需要专业人员确认的事项。

## 使用边界

本知识库是研究、学习和工作辅助工具，不替代注册会计师、企业管理层或其他专业人士结合完整事实作出的正式判断。资料可能存在版本差异、后续修订或尚未完成摄入的部分，使用者应核对规则的生效状态和原始文件。未经授权的准则汇编、商业实务资料、客户信息、项目底稿、个人笔记、账号和密钥不应上传到公开仓库。

### 对外简短介绍

这是一套面向财务、审计和会计咨询工作的企业会计准则专业知识库。它把准则原文、应用指南、准则解释、财政部问答、应用案例和实务资料整理成结构化知识页，让重要结论能够回到原文具体段落核对。知识库不仅保存文件，还持续沉淀专业概念、子专题、会计判断、证据要求和资料之间的关联，并使用 Markdown 与 Git 保存知识的来源和演进过程。

## 版本二：企业微信协作版（包含企业微信机器人）

### GitHub 仓库简介

基于 GroundMap 构建的企业会计准则专业知识库，提供 Web 管理台和企业微信只读查询机器人，支持准则原文溯源、统一查询链路、逐用户查询留痕、知识健康检查与 Git 审计。

### README 开篇介绍

## 项目简介

这是一个面向财务、审计、会计咨询和企业财务报告团队的企业会计准则专业知识库与企业微信查询服务。底层知识库以 Markdown + Git 保存准则原文、应用指南、准则解释、财政部实施问答、应用案例、监管规定和实务分析；专业人员可以在 Web 管理台中浏览、维护和复核知识，普通使用者可以直接在企业微信中提出日常工作问题。

企业微信机器人不是另一套知识库，也不自行维护专业资料。它作为 GroundMap 的外部只读客户端，与查询控制台共用查询规划、全文检索、原文核验、引用校验和答案生成链路。机器人只返回最终答案和来源，不直接修改 Markdown，不向普通测试人员开放资料上传、知识编辑或管理操作。

知识内容按照“来源 - 概念 - 子专题 - 分析 - 索引”组织：以基本准则和第 1 号至第 42 号具体准则为主干，关联应用指南、准则解释、财政部问答、应用案例和实务资料。团队成员可以询问具体会计处理、报表列示、披露要求、审计关注事项和所需证据；管理员则通过 Web 管理台完善知识，并在查询控制台观察回答质量和知识缺口。

## 核心能力

- **双入口使用**：Web 管理台用于浏览、维护、复核和治理，企业微信用于现场快速查询。
- **统一回答链路**：机器人和查询控制台共用同一套检索与原文核验流程，避免两个入口采用不同知识或不同提示逻辑。
- **专业化回答结构**：回答可以区分结论、适用前提、准则依据、分析过程、所需证据、披露要求和风险提示。
- **答案附带来源**：返回相应准则、解释、问答、案例或知识页；部署受控访问地址后，可以提供可点击的原文引用链接。
- **精确问题回查原文**：遇到条款、数字、日期、例外条件或重大判断时，从知识页继续下钻到原文锚点进行核验。
- **只读安全边界**：机器人通过 HTTP 接口查询，不直接读写知识库文件，不开放摄入、编辑、删除或管理权限。
- **成员范围控制**：企业微信后台的可见范围与本地查询白名单共同限制测试人员，可以先向少量成员开放。
- **逐用户查询留痕**：本地记录问题、回答、状态、耗时和引用来源；用户标识经过 SHA-256 匿名化，不在管理页面显示原始企业微信账号。
- **历史答案复用**：当问题语义和关键条件兼容时复用已有答案，降低重复模型调用；需要重新核验时可以强制刷新。
- **多企业配置隔离**：不同企业使用独立 Bot 凭据、成员白名单和查询数据库，共用知识引擎但不共用身份配置。
- **查询反哺知识库**：管理员可以从高频问题、失败查询和低质量回答中识别资料缺口，再补充来源或完善专题页面。
- **全过程可审计**：知识内容由 Markdown 和 Git 管理，机器人运行记录保存在本地数据库，两类记录各自承担知识审计和使用审计功能。

## 典型使用流程

1. 管理员将获准使用的准则、解释、问答、案例和实务资料放入受保护的原始资料目录。
2. 外部 AI agent 阅读完整页面或章节，建立来源摘要，并更新专业概念、子专题、索引和分析页面。
3. 财务或审计人员在企业微信中描述交易背景并提出具体问题。
4. 机器人调用统一查询接口，定位相关概念和来源；涉及精确依据时继续回查原文块。
5. 使用者收到结论、适用前提、依据、证据建议和引用来源，并根据实际业务补充事实。
6. 管理员在测试记录中查看成功率、耗时、引用和错误，识别高频问题与知识缺口。
7. 对有长期价值的问题补充资料或形成专题分析，使后续查询建立在更成熟的知识页上。

## 安全与治理说明

- 机器人凭据、模型密钥、成员白名单和查询数据库仅保存在本地忽略文件中，不进入 Git。
- 每个企业应创建自己的机器人，不复制其他企业的 Bot ID、Secret 或成员身份配置。
- 企业微信“可见范围”决定成员能否找到机器人，本地白名单决定成员能否执行查询，两者需要分别配置。
- 对外提供原文链接时，应使用经过身份认证的访问地址，不能向远程成员发送 `localhost` 链接。
- 查询记录属于运行数据，应事先明确告知范围、保存期限、访问权限和清理机制。
- 原始资料可能包含版权内容或客户信息，应与公开代码仓库隔离，并按照组织的数据安全制度管理。
- 机器人回答属于专业辅助信息，重大会计处理、审计结论和对外披露仍须由具备职责的专业人员复核。

### 对外简短介绍

这是一套可以通过 Web 和企业微信使用的企业会计准则专业知识库。团队成员可以直接在企业微信中询问会计处理、报表列示、披露要求和审计证据等问题，机器人从经过整理的知识页中查询，并返回带来源依据的回答。管理员可以查看匿名化测试记录，发现高频问题、失败查询和知识缺口；底层知识则通过原文块级引用、健康检查、Markdown 和 Git 保持可核验、可维护和可追溯。

## GitHub 发布建议

公开发布前，建议只提交以下内容：

- GroundMap 引擎代码、公开文档、页面模板和不含敏感信息的示例知识页；
- 已确认有权公开的自有分析、演示资料和脱敏示例；
- 环境变量模板，但不包含任何真实 Bot ID、Secret、模型密钥、成员 ID 或内网地址。

以下内容不应进入公开仓库：

- 未获公开授权的准则汇编、实务指引、培训资料、商业数据库内容及其他受版权保护的原件；
- 客户资料、项目底稿、个人笔记、测试人员身份信息和查询数据库；
- `.env.local`、机器人实例配置、API 密钥、访问令牌和私有服务器配置。

如果要同时公开引擎并保留私人专业资料，建议把开源引擎与知识数据拆分：公开仓库只放 GroundMap 引擎和可公开示例，真实知识库放在独立私有目录或私有仓库中，并通过 `KB_ROOT` 接入。
